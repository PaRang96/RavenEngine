# Coding rules

Adopted by the owner on 2026-11-27 (joint review of M6A and M6C, item 5), condensed from rules R1–R15 of the [code-quality assessment](CodeQualityAssessment-2026-11-26.md#7-proposed-coding-quality-rules-for-the-team). They apply to every contributor and to assistants. Each rule names the findings it would have prevented. `AGENTS.md`, which is local, points here; the layout, naming and component rules stay in `AGENTS.md`.

1. **One fact, one place.** When a fact (a kind list, a rule, a layout, a limit, a name) would appear a second time, make it a table or a function first. A dispatch over a closed set throws on the unknown case instead of falling through to a default. Before writing a helper (a result check, a slot map, a barrier, a script's folder list or key table), use the subsystem's shared one. *(Was R1, R6 and R12; CQ-X-01, CQ-X-03, CQ-RND-01, CQ-DATA-01, CQ-DATA-02, CQ-VK-01, CQ-MEDIA-05, CQ-GAME-05, CQ-BLD-01.)*
2. **Mirrors copy whole.** A struct that mirrors another's state stores the source struct as one member and assigns it whole, never a hand-copied field list. *(R2; CQ-GP-01.)*
3. **Comments change with behavior.** A change to behavior, cost or a capability updates the comment, error text and doc line that describe it in the same commit. A comment never claims a check, cost or mode the code does not have. *(R3; CQ-X-04, CQ-X-09, CQ-API-02.)*
4. **Persisted values are marked.** A function whose output is written to a file or compared with stored data carries a "file format; never change" comment, and lives apart from in-memory digests. *(R4; CQ-X-02.)*
5. **Check before dereferencing.** Game code never writes `TryGet(...)->`. Optional and data-dependent reads use a checked `TryGet` or `Read` and skip with one log line, so the system recovers as soon as the data is fixed. A throwing `Get` is only for true invariants, because a system that throws stays suspended until the next code reload. *(R5; CQ-GAME-01.)*
6. **Name tuning.** Every tuning or capacity number gets a named constant with a one-line reason. Designer-visible ones are listed in the subsystem's doc. *(R7; CQ-X-07.)*
7. **Work rides with its step.** A function that the next milestone step edits, and that is over about 80 lines or does more than one job, is split in that step's commit series, never in a separate polish pass, and never when a later step deletes it. Every "delete with Bn" note is listed in that step's checklist once its design is settled, so the step removes everything at once. *(R8 and R13; CQ-X-05, CQ-RND-02, CQ-VK-12.)*
8. **Hot paths allocate only to grow.** Per-frame and per-step code reuses buffers (clear, keep capacity) and avoids building strings and per-entity hash lookups. New exceptions are listed in the AA2-PERF-09 inventory. *(R9; CQ-X-06.)*
9. **State callback contracts, and keep `noexcept` true.** An interface whose callbacks run under a lock says so, and says which calls they must not make. A `noexcept` function, or a callback its caller does not wrap in `try`, never calls anything that throws; it uses the non-throwing form and its own reject path. Everything a third-party library calls back into (Jolt, the audio device) is `noexcept`. *(R10 and R14; CQ-CORE-03, CQ-GP-13, AA2-RT-04.)*
10. **Batch contract-hashed edits.** Changes to public headers and other game-contract inputs go into the current phase's single batch, so games rebuild once per phase. *(R11; CQ-X-08.)*
11. **Registration rejects ambiguity.** A table that could be read two ways (an alias chain, one old name claimed twice, an unclassified program) is rejected when it is registered, never resolved by iteration order. *(R15; CQ-DATA-02, CQ-RND-01.)*
